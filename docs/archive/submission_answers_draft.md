# Submission Answers Draft

## 1. 무엇을, 누가, 어떤 상황에서 쓰나요?

마이리얼트립 사용자가 YouTube URL, 블로그 링크, 일반 여행 링크, 자연어 여행 요청을 실제 여행 일정으로 옮기고 싶을 때 쓰는 AI 여행 플러그인입니다. 첫 해외여행을 준비하는 사용자, 부모님과 동행하는 사용자, 특정 취향의 장소를 모아보고 싶은 사용자가 콘텐츠를 보면서 따로 장소를 복사하고 Day별 일정을 만드는 상황을 줄이는 것이 목표입니다.

## 2. 왜 이 문제를 선택했나요?

여행 콘텐츠는 많지만, 콘텐츠를 실제 예약/동선/일정 단위로 옮기는 과정은 여전히 번거롭습니다. 사용자는 영상이나 블로그에서 장소를 찾고, 지도에서 다시 검색하고, 날짜별 순서와 카테고리를 직접 정리해야 합니다. 마이리얼트립은 여행 탐색과 실행이 이어지는 서비스이므로, 콘텐츠를 바로 편집 가능한 일정으로 바꾸는 문제가 기업 맥락과 잘 맞는다고 판단했습니다.

## 3. 플러그인은 어떻게 작동하나요?

사용자가 링크 문자열, 텍스트, 직접 입력한 여행 조건을 넣으면 AI가 제공된 입력과 여행 조건을 구조화해 Day와 블록 단위 일정으로 변환합니다. 현재 MVP는 영상 자막 전체 추출이나 모든 블로그 본문 완전 크롤링보다, 입력 정보를 편집 가능한 일정 블록으로 바꾸는 흐름에 집중합니다. 생성된 블록은 숙소, 음식점, 카페, 관광지, 액티비티, 이동 같은 카테고리로 표시되고, 사용자는 블록을 추가, 수정, 삭제, 이동, 연결, 저장할 수 있습니다. 저장된 일정이 있으면 다음 진입 시 여행 목록을 보여주고, 저장된 일정이 없으면 신규 이용자 화면을 보여줍니다.

## 4. AI를 어떻게 활용했나요?

웹 UI에서는 Gemini를 서버 proxy에서만 호출해 실제 AI 여행 일정 생성, 링크/텍스트 기반 일정 구조화, 추천 블록 생성을 구현했습니다. Codex MCP 도구는 API 키 없는 심사 환경을 위해 도시, 일수, 테마를 추출하는 입력 기반 deterministic fallback을 제공합니다. 프론트엔드는 API 키에 접근하지 않고 내부 API만 호출합니다. 추천 블록은 현재 여행 도시, 선택된 Day의 city/region, 기존 장소 목록을 입력으로 받아 3~5개의 장소를 생성하고, 기존 장소와 중복되는 추천은 제거합니다. 장소 검색은 OpenStreetMap/Nominatim을 사용해 실제 서비스형 검색 흐름에 가깝게 구성했습니다. Codex는 구현 과정에서 코드 수정, MCP 서버 정합성 점검, fallback 검증, 문서 정리에 활용했습니다.

## 5. 어떻게 검증했나요?

Mock OFF 상태에서 AI 일정 생성, Gemini 추천 블록, 저장/불러오기, 첫사용자/기존사용자 화면 전환, 연결 기능, 새로고침 후 복구 흐름을 수동으로 확인했습니다. 또한 `npm run lint`, `npm run build`, `npm run test:mcp`, MCP initialize/tools/list/tools/call, 입력별 deterministic fallback 차이, API 실패 fallback을 검증했습니다. Playwright smoke test도 추가해 첫 진입, 일정 생성, 추천 호출, 저장, 목록 이동, 다시 열기, 연결 모드, 새로고침 복구를 자동 검증하도록 했습니다. Real API 실패, timeout, JSON 파싱 실패 등은 기존 Mock fallback으로 이어지도록 구성했습니다. 현재 한계는 DB 영구 저장과 실제 영상 분석 고도화가 아직 추후 개선 단계라는 점입니다.
