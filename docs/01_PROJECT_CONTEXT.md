# 01_PROJECT_CONTEXT.md

## 1. 프로젝트 개요

프로젝트명: Travel Blocks AI

대상 기업: MyRealTrip

한 줄 설명:

Travel Blocks AI는 영상, 링크, 텍스트, 여행 요청사항을 AI가 분석하여 여행 일정을 블록 형태로 생성하고, 사용자가 레고처럼 여행을 조립·수정·저장·내보내기 할 수 있는 AI 여행 일정 생성 Codex Plugin이다.

## 2. 해결하려는 문제

기존 여행 계획 서비스는 보통 텍스트 중심의 일정표 형태다.

사용자는 다음 문제를 겪는다.

1. 유튜브, 블로그, SNS에서 본 여행 정보를 직접 정리해야 한다.
2. 장소, 숙소, 식당, 이동수단을 한눈에 조립하기 어렵다.
3. Day별 일정을 비교하거나 옮기는 과정이 불편하다.
4. 예산, 동선, 추천 이유가 일정 편집 과정에 자연스럽게 반영되지 않는다.
5. 완성한 일정을 보기 좋은 형태로 공유하거나 내보내기 어렵다.

Travel Blocks AI는 이 문제를 “여행 블록” 단위로 해결한다.

## 3. 핵심 제품 컨셉

Travel Blocks AI의 핵심은 다음 세 가지다.

1. AI가 여행 정보를 분석한다.
2. 분석 결과를 여행 블록으로 변환한다.
3. 사용자가 블록을 조립하듯 일정을 편집한다.

즉, 단순한 여행 일정표가 아니라 “AI 기반 여행 블록 조립 도구”를 목표로 한다.

## 4. 주요 기능 요약

### 4.1 여행 생성

여행 생성 방식은 세 가지다.

1. 새 여행 직접 생성
2. AI 요청 기반 여행 생성
3. 링크/텍스트/영상 분석 기반 여행 생성

### 4.2 여행 블록 편집

사용자는 생성된 여행 블록을 다음과 같이 편집할 수 있어야 한다.

- 추가
- 수정
- 삭제
- 이동
- Day 간 이동
- 추천 블록 삽입
- 검색 결과를 블록으로 변환
- 블록 간 연결선 추가
- 연결선 삭제
- 연결선에 교통수단 추가

### 4.3 Day 관리

Day 관리는 브라우저 탭처럼 동작한다.

- Day 추가
- Day 삭제
- Day 이름 변경
- 단일 Day 보기
- Split View
- Detach View

### 4.4 AI 보조 기능

AI 보조 버튼 또는 사이드 패널을 제공한다.

역할은 단순 챗봇이 아니라 여행 일정 편집 도우미다.

예시 기능:

- 빈 시간 채우기
- 예산 줄이기
- 동선 최적화
- 맛집 추천
- 비 오는 날 대체 일정 추천
- 영화/드라마 촬영지 추천
- 추천 결과를 블록으로 추가

### 4.5 저장 및 내보내기

- 여행 저장
- 저장된 여행 목록 보기
- 저장된 여행 불러오기
- 블록형 일정을 예쁜 텍스트 일정으로 내보내기
- 복사하기 기능 제공

## 5. 해커톤 제출 구조

제출 구조는 반드시 다음 형태를 따른다.

```text
submission.zip
├── src/
│   ├── .codex-plugin/plugin.json
│   ├── skills/<이름>/SKILL.md
│   ├── .mcp.json
│   └── 그 밖의 실행 코드와 설정 파일
├── README.md
└── logs/

중요 조건:

전체 플러그인 루트는 반드시 src/ 내부에 있어야 한다.
src/.codex-plugin/plugin.json은 필수다.
플러그인이 실제로 동작하는 구성 요소가 하나 이상 있어야 한다.
skills/<이름>/SKILL.md, MCP 서버, 실행 코드 중 하나 이상을 포함해야 한다.
README.md는 프로젝트 설명, 실행 방법, 검증 방법을 포함해야 한다.
logs/ 폴더에는 AI와 작업한 전체 로그를 원본 그대로 포함해야 한다.

###6. logs 폴더 및 log-hooks

해커톤 제출 시 AI와 주고받은 전체 대화 로그를 logs/ 폴더에 포함해야 한다.

로그는 다음 조건을 지켜야 한다.

편집 금지
발췌 금지
삭제 금지
사후 가공 금지
원본 그대로 제출

Codex CLI 또는 Claude Code를 사용할 경우 log-hooks 도구를 설치해야 한다.

다운로드 주소:

https://github.com/jocoding-ax-partners/axwar/releases/download/v1.0/log-hooks.zip

설치 방식:

위 ZIP 파일을 다운로드한다.
작업 폴더 루트에 압축을 해제한다.
Codex CLI 최초 실행 시 훅 신뢰 여부를 묻는다면 승인한다.
이후 대화 로그가 logs/ 폴더에 자동 저장되는지 확인한다.

주의:

API 키
비밀번호
토큰
개인 인증 정보

위 정보는 AI 채팅이나 로그에 절대 남기지 않는다.

###8. 아키텍처 원칙

코드는 다음 원칙을 따른다.

기존 프로젝트 구조를 먼저 분석한다.
기존 UI와 아키텍처를 최대한 유지한다.
기능을 무리하게 갈아엎지 않는다.
컴포넌트는 역할별로 분리한다.
타입은 명확히 작성한다.
Mock 데이터는 별도 파일로 분리한다.
상태 관리 로직은 hooks 또는 utils로 분리한다.
외부 API 실패 시 Mock 데이터로 fallback한다.
에러가 발생해도 앱이 죽지 않게 처리한다.
콘솔 로그와 에러 메시지는 한국어로 작성한다.

###9. Mock AI 원칙

현재 실제 외부 AI API가 없거나 심사 환경에서 API 호출이 불안정할 수 있으므로 Mock AI 모드를 기본 지원한다.

요구사항:

USE_MOCK 또는 유사한 상수로 Mock 모드를 쉽게 켜고 끌 수 있어야 한다.
Mock 모드에서도 실제 서비스처럼 자연스러운 결과가 나와야 한다.
링크 분석, AI 요청 기반 생성, 추천 블록, AI 보조 기능은 Mock 응답으로라도 동작해야 한다.
API 실패 또는 timeout 발생 시 Mock 데이터로 대체한다.

11. 최종 목표

Travel Blocks AI는 단순한 여행 일정표가 아니다.

최종 목표는 다음과 같다.

사용자가 유튜브, 블로그, 텍스트, 직접 입력한 여행 요구사항을 기반으로 AI가 여행 블록을 생성하고, 사용자는 그 블록들을 Day별로 조립하면서 예산, 동선, 교통수단, 추천 이유를 함께 확인할 수 있는 AI 여행 계획 플러그인을 만드는 것이다.
